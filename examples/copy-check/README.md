# 复制完一批文件，怎样确认副本齐全？

把源目录和副本的每个普通文件按相对路径配对，再分别读取字节计算 SHA-256。即使文件名相同、大小也相同，只要内容改变，结果就会列出差异。工具可以断网运行，所需环境为 Python 3.12 或更新版本。

## 先照做一次

从项目根目录打开终端，使用随包的两份虚构资料生成报告。两个目录各有一份说明和一张嵌套在 `labels` 子目录的卡片。报告须放在待核目录外，且使用尚未存在的文件名。

~~~sh
python -B -X utf8 examples/copy-check/compare.py --source examples/copy-check/demo/source --copy examples/copy-check/demo/copy --output copy-report.json
~~~

打开新生成的 `copy-report.json`。应看到 `result` 为 `match`、`same` 为 2；两行中源和副本的字节数及 SHA-256 分别相等。项目中的[示例报告](expected.json)保留了这两个文件的预期结果。

| 报告标记 | 怎样读 | 怎样处理 |
| --- | --- | --- |
| `same` | 同一相对路径，内容相同 | 保留本次对账记录 |
| `missing` | 源中有，副本缺失 | 核对来源后把缺件复制到正确的相对路径 |
| `extra` | 副本有，源中没有 | 核对是否是已有工作文件或改名项，保留并查明来历 |
| `changed` | 同一路径，字节不同 | 保留两个版本，确认哪份应作为本次源文件 |

## 换成自己的目录

1. 先让复制完成，关闭正在修改这批文件的软件。选两个互不包含的本机目录，分别替换命令中的 `--source` 和 `--copy`。把路径含空格的参数用双引号括起。
2. 在两个目录之外另取报告名。原文件、旧报告和多余文件都保留。输出只记录相对文件名、字节数和哈希，真实业务的文件名也可能含隐私，请将真实报告保存在本机私有位置。
3. 先看总数，再读差异行。文件移动、改名和大小写变化按完整相对路径表现为缺失和多出。可结合哈希与文件来源核对，遇到内容相同的多份资料也要核对用途。
4. 差异修复或新一批复制完成后，另存 `copy-report-v2.json`。退出码 0 表示两侧至少有一个文件且普通文件全部相同；1 表示已有差异报告或两侧都没有普通文件；2 表示参数、路径、链接、权限或读取过程出错，需处理报错后重试。

**自己制造一个差异。** 另复制演示的两个目录，在副本的卡片中将 `A6` 改为 `A5`，保留编码和换行。新报告应有 1 个 `same`、1 个 `changed`。如这项同时被移到别的子目录，则应列为 1 个 `missing` 和 1 个 `extra`。

**范围。** 比较普通文件内容，包括嵌套文件和隐藏文件。工具拒绝链接、目录联接及特殊文件。空目录结构、权限、时间戳、扩展属性和内容是否能被业务软件打开，需要按实际交付要求另查。本工具读取指定路径下当前可读的数据；使用时选本机存储、保持两侧静止。哈希一致也不证明两份数据位于独立物理设备。

**可给 AI 的提示词。** “请用这份虚构报告按相对路径列出缺件、多件和内容差异，解释下一步应核哪一份。将同名同大小但哈希不同的资料单列，保留所有原件，待我确认处理方式。”
