# 把期间核销与同批购券分开对账

周末看到“净核销 3、这周卖出的券只用掉 2”，可以先核对这两张表。前者按事件发生日期计数，其中可能有上周买的券；后者只跟踪这周购买的券。本例按券编号连接支付表和事件表，同一订单可以包含多张券。

## 第一次复算

打开[虚构输入](demo.json)和[预期结果](expected.json)。统计区间为 5 月 1 日至 7 日（含两端）。A 是上月购买、本期核销。B 本期核销后撤销，又成功核销。C 与 B 同单，C 单独退款。D 的同一条核销事件重复导出一次。E 到 9 日才使用。F 在统计期后购买。

| 读哪组数据 | 手算结果 |
| --- | --- |
| 本期发生的事件 | A、B 两次、D 共 4 次核销；撤销 1 次；净核销 3 次。C 退款 1 张。 |
| 本期支付批次截至 7 日 | B、C、D、E 共 4 张；B、D 已用，C 已退，E 待使用。支付券核销率 2/4（50%），分母含后来退款的券。有效券核销率 2/3。 |

在项目根目录运行以下命令，打开生成的 JSON 与上表对照。只需要 Python 3.12 或更高版本。

~~~sh
python -B -X utf8 examples/voucher-review/reconcile.py --input examples/voucher-review/demo.json --output voucher-review.json
~~~

## 换自己的输入

复制示例到本机私有目录。两张表都使用同一门店时区。支付表 `paid` 一张已支付的券一行，填匿名券编号 `voucher`、匿名订单编号 `order` 和支付时刻 `paid_at`。事件表 `events` 填稳定事件编号 `id`、券编号、发生时刻 `at` 和动作 `action`。同一订单中的每张券单独编号。相同业务券必须在两表使用相同匿名编号；只提供计算所需字段。

取本期购券及本期事件涉及的所有券，保留它们自支付起的完整事件历史。撤销上期核销时，本期净核销可以为负。输入时间统一为 `YYYY-MM-DD HH:MM:SS`。已用券撤销记 `reverse`，未使用券完整退款记 `refund`，核销记 `redeem`。退款为该张券的终止状态；金额部分退款、跨门店对账及费用归因需要另有口径和数据。分母为零时显示“无可计算分母”。

**验证一次。** 保持原输入，把截止日改到 9 日，换一个输出文件名。E 应转为已用，F 进入支付批次，得到已用 3 张、支付 5 张、有效 4 张。再将一个撤销事件的券编号改为未核销的券，程序应停止并指出冲突。请核对历史记录、纠正源表副本，再生成新结果。重复的同一事件只计算一次，冲突事件、孤立记录和重复 JSON 字段均会停止计算。

**给 AI 的提示词。** “请用下面两张虚构表，先按事件发生日计算本期核销、撤销和退款，再按每张券的支付日筛选本期批次，列出截至期末的状态。解释上期券和同单多券造成的差异，把无法确认的记录列出来。先手算预期，再用工具复算。”

此工具统计券数。判断活动盈亏、投放归因或实际到账，还需要核对结算、费用和相应业务凭据。
