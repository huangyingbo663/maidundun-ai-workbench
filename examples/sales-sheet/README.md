# 制作一份销售确认单

手头已有双方核过的商品、规格、数量和单价时，用这份工具制作可阅读、可打印的单据。把 JSON 作为可编辑源文件，把生成的 HTML 作为对客阅读版。输出固定写明版本、日期和人民币。只需 Python 3.12 或更新版本。

## 第一次跑通

[输入示例](demo.json)是虚构文具订单。三本笔记本单价 8.35 元，小计 25.05 元；四份书签单价 2.10 元，小计 8.40 元。读者应看到货款小计 **33.45 元**与“运费另算”，最终含运费总额留待确认。[查看示例成品源码](expected.html)

~~~sh
python -B -X utf8 examples/sales-sheet/generate.py --input examples/sales-sheet/demo.json --output confirmation.html
~~~

双击刚生成的 HTML，在浏览器里打开打印预览，检查最后一行与运费说明。若想直接看成品，下载项目 ZIP 并在解压目录双击 `examples/sales-sheet/expected.html`。

## 换一份单据

1. 把示例复制到本机的私有工作目录，逐行填商品、规格、整数数量及含两位小数的单价字符串。商品名与规格分别最多 80 个字符，版本最多 32 个字符；运费及单价最高 999999999.99，单行数量最多 999999。金额按整数分计算。
2. 运费已确定时填 `"shipping": {"mode":"fixed","amount":"6.50"}`。免运费填已确定的 `"0.00"`。运费待核保留 `{"mode":"separate"}`。重算示例时，已确认运费 6.50 元应得到含运费合计 **39.95 元**。
3. 修改商品数量后递增版本，输入、输出都使用新文件名。最后一行书签从 4 改为 5，运费仍为 6.50 时，含运费合计应为 **42.05 元**。
4. 先检查对客品名、规格、数量、单价、币种、运费和版本，再把适用版本交给收件人。真实业务留在本地；把成本、进价、库存、联络信息等额外列混入输入会触发拒绝。商品名称等自由文字仍需人工核对。销售确认单的生成和实收、发货由各自流程记录。

**失败恢复。** 金额精度错误、重复或意外字段、已有同名输出都会停止生成。先修正源文件副本并核对输入格式，再另取输出名执行。

**给 AI 的提示词。** “请用我提供的虚构对客条目核对规格和数量。按分计算每行金额，区分运费已确认和另算，输出销售确认单所需的最小字段。列出缺项；在新版本复核最后一行与合计。”
