# 门店低库存，冷库该去核哪几款？

店长拿到门店账存和冷库台账，想先找“店里低于指定数量，冷库确实有可调账存”的商品。这份离线工具把同一清单分成**账面候选、待核、本次筛除**三栏，给取货人一张能拿去现场核数的文字清单。适合按个、件、袋等整数单位计数的货品。

## 先看一个例子

假设筛选线为 30 件。晨雾方糕门店有 29，冷库账存 12、预留 2，能调 10，补到筛选线只差 1 件。琥珀小枕门店有 4，冷库账存 7、预留 2，最多能从这批账存中补 5 件。门店正好有 30 件的月纹薄饼进入“本次筛除”。这些名称和数字均为虚构。[完整输入](demo.json) · [完整核数清单](expected.txt)

**第一次使用。** 从项目根目录打开终端，电脑安装 Python 3.12 或以上即可。运行后双击新生成的 `stock-pick.txt`，对照上述两个数，再看“待核”栏的原因。

~~~sh
python -B -X utf8 examples/stock-pick/plan.py --input examples/stock-pick/demo.json --output stock-pick.txt
~~~

示例共 10 行，按唯一货号合并判断为 9 款。其中 2 款账面候选、4 款待核、3 款筛除。上限合计 6 件。这一数字只描述补到测试筛选线的空间。店长最终选多少，还要看销量、需求与能放多少。

## 换自己的输入

1. 复制 `demo.json` 为 `my-stock.json`，保存在本机私有目录。决定这次盘哪些在售货品，以及用多少件作为筛选线。
2. 取两个来源的实数与各自的快照时间。按唯一 SKU 对齐门店与冷库，保留没有匹配成功的行，用 `null` 标记未知。SKU 按文字匹配，大小写有区别，前导零应保留。仅名称相似、不同规格或计量单位不同的商品先核身份。
3. 将 `items` 换成自己的列表。每个 SKU 一行，所有数量采用同一计量单位。若原表按批次拆行，先在私有底账核对实物、日期、可售状态及重复后再汇总；保留原批次以便现场按批取货。
4. 将命令中输入位置改为自己的 JSON 路径，输出文件另命名为 `stock-pick-v2.txt`。两个来源间若有时间差，先查期间的进出、预留及待到店记录。核完再按相同口径重跑。

| 字段 | 怎样填写 |
| --- | --- |
| `threshold`、`unit` | 正整数筛选线、共用计量单位。30 是案例取值，可改。不同单位请分表。 |
| `store_as_of`、`cold_as_of` | 门店和冷库各自取数时刻，用含时区日期时间，例如 `2025-03-08T11:30:00+08:00`。即使两项相同，也要确认它们适用于本次作业。 |
| `sku`、`name` | 带引号的唯一货号、供核数人辨认的品名。 |
| `store`、`cold` | 门店账面库存、冷库当前账存。冷库账存填写扣除预留**之前**的数量。若手头只有已经净扣预留的数，先统一口径。 |
| `reserved` | 已包含在冷库账存中、这次不能调出的数量，如已承诺预留或已经核清的不可用量。 |
| `in_transit` | 此 SKU 已有在途调货数量。确认没有才填 0，有在途先核实收货状态再算。 |

每个数量填整数或 `null`。缺失、负数、数值类型错误、预留大于冷库账存、已有在途以及重复 SKU，都会进入待核。身份、时间、表头或 JSON 本身有误会中止生成，避免把错误清单当作完整结果。

## 怎样判断和执行

当门店低于筛选线、冷库可调量为正且行内数据通过检查，该款才入候选。冷库可调量 = 冷库账存 − 预留。补到筛选线的参考上限 = 门店缺口与冷库可调量中的较小值。输出按货号排序。

操作人接着核三件事。先核冷库实物、生产日期、可用批次、尚未入账的出入库和上一批实际是否到店。再结合门店近期售出速度、店长反馈、陈列/储存空间及日期确定实际提几件。最后按现行业务制度记录实际取货、到店品种与数量并排重。该脚本只读输入并生成本地文字清单，实际调拨和两地登记需要单独执行。

## 检验与恢复

把示例的 `threshold` 改为 5 并另存一份。账面候选应只剩门店 4 件的琥珀小枕，参考上限应为 1。再把该项 `reserved` 改为 8，大于冷库账存 7，应进入待核。工具拒绝覆盖同名输出；改用新文件名，保留旧稿比较。若报字段或时间格式错，按示例改输入后重跑。修正异常应依据实物与原账。
