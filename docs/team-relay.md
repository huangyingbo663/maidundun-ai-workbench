# 跟做一次接力：把活动指引卡交到下一人手上

准备三个角色：负责人安排依赖，写者交稿，另一位复核者打开文件核对。用三个人、三个独立会话，或一个写者加一位同事都可以。若只有自己，先做自检，等第二个人来读再记独立验收。工具没有 Python 以外的安装依赖。下文命令从解压后的项目根目录运行，报告写在项目旁边。

## 第一步　负责人派工

打开[派工输入](../examples/work-brief/sample.json)，按任务 ID 找到三行。先由事实整理者维护已确认的活动规则，再由文案写者独占 `materials/card-copy.md`，文案通过后排版者才处理 `materials/print-card.md`。可以把下面一段及输入文件交给负责分工的助手。

> 目标是让第一次到场的人知道去哪里领、到哪里体验、走前把借物还到哪里。请读活动事实和派工输入，列出每项的前置任务、唯一写者、交付文件和可观察的通过标准。告诉我现在谁能开工、谁还要等。两人认领同一文件时先解决归属，再交付任务。

~~~shell
python -B -X utf8 examples/work-brief/plan.py examples/work-brief/sample.json --out ../work-board-v1.md
~~~

打开生成的 `work-board-v1.md`，和[预期看板](../examples/work-brief/expected.md)逐项对照。能开始写文案时，排版仍有等待条件。更换写者时，原写者先停止编辑并交出采用版本，负责人更新认领，新写者重新打开文件再改。

## 第二步　写者交稿，复核者实际读稿

> 写者：只用已确认的活动事实，写出“领取、体验、归还”三步。把稿子写进分给你的文件。交稿时告诉下一人文件位置、改了什么、哪一项还须现场验证。拿不到活动时间或展示架尺寸时，把缺项写在交接里。

演示包提供两个阶段的快照。派工时文案产物叫 `materials/card-copy.md`，接班练习里同一稿件的交付副本叫 `artifacts/guide.md`。任务 ID 都是 `copy`。实际使用时，由交稿人交付选定的那一版并记录其位置。两个工具分别读取各自的 JSON；派工板的输出不会更新交接文件。

> 复核者：用活动事实逐句对交稿，确认领取点、体验地点和归还点都写清楚。记录你打开的文件、版本、每项是否通过和理由。地点有错就指出哪一行应退回；看到“已完成”的消息也要打开当前文件。现场摆放留给实际到场的人验。

现在请亲自对照[活动事实](../examples/work-brief/materials/event-facts.md)和[当前指引卡](../examples/handoff-check/artifacts/guide.md)。先说出三个答案，再打开[示例复核回执](../examples/handoff-check/reviews/guide.json)。文件摘要（SHA-256）像指纹，可判断复核者读过的字节是否和今天这份一致。内容正确、现场可见仍要有人分别核实。

## 第三步　换一个人，只给交接目录

~~~shell
python -B -X utf8 examples/handoff-check/check_handoff.py --input examples/handoff-check/sample.json --output ../handoff-v1.json
~~~

让新接手的人只读生成的报告和它引用的文件。请他说出三件事：`copy` 的哪一版已经通过？`onsite` 由谁到现场看、需要留下什么？`layout` 在等谁提供什么？如果接班人需要上下翻旧聊天才能回答，请把缺的材料、位置或动作补回交接，再换人读一次。

**试一次改版。** 把整个 `examples/handoff-check` 目录复制到项目旁，副本名为 `handoff-practice`。在副本的 `artifacts/guide.md` 中改一个字，保存。运行下面的命令，新报告名保留第一次的结果。

~~~shell
python -B -X utf8 ../handoff-practice/check_handoff.py --input ../handoff-practice/sample.json --output ../handoff-v2.json
~~~

找到 `copy` 的结果。旧回执对应旧文件，新版本需要重新复核。要保留改动，由复核者重新读新稿、按标准判定，再更新其负责的复核记录。若改错了，用随包的原件还原副本文稿。用新的输出名再运行一次。完整字段和异常处理见[交接工具说明](../examples/handoff-check/README.md)。

## 带走一张空白交接卡

复制下列内容填在自己的项目里。一次只写一个产物，下一人可以照着这几行直接继续。

~~~text
目标和实际使用者：
任务 ID / 依赖：
唯一写者 / 写入哪份文件：
当前采用文件 / 版本：
如何算通过（接班人能实际观察什么）：
谁独立看过 / 复核回执在哪里 / 对应哪一版：
状态（可开工、待复核、受阻、待现场、已验收）及依据：
下一位负责人 / 第一项具体动作 / 何时应停下来等待：
~~~

两人同时报“我来改”，先确认谁持有最新稿。写者已交稿但没有复核记录，把文件交给复核者。任务需要进店看摆放时，留给现场同事，收到现场记录后再更新交接。[返回场景](team-collaboration.md)
