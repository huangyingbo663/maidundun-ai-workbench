# 四个补充分支

已有一个完整动作、一个产品问题或一个工具流程，不一定要硬套主风格。下面四种方法都有独立入口。用自己的素材和事实开始，交完整作品与可恢复工程。

## 10｜沉浸摆货、动作小剧情、观察互动

**输入：** 完整工作原片，能看到起态、变化与终态；声音可用条件；不宜公开的人物或信息。

**选择：** 沉浸摆货让观众看完整变化；动作小剧情由真实动作产生转折；观察互动给一个画面能够回答的问题。不能同一条片换三个标题就算三种制作。

**步骤与工具：**

1. 先完整看动作，再写一句观看任务，如“从空到摆齐”或“找最后调整的物件”。不从一张抽帧编心理。
2. 在剪辑软件或 FFmpeg 中选完整区间，保留承重动作和结尾，跳切只省等待。变速如实记录，不当真实耗时。
3. 声音选原环境声、解释性旁白或音乐。原声要完整听净；ASR 没识别到字不代表没有不宜公开的谈话。
4. 用最少的字给观看理由，别挡手和物品。封面取本条真实画面，问题必须能由结尾动作回答。
5. 全片看听，检查动作连续、物体位置、隐私、声音衔接，交工程、封面、文案和记录。

可复制提示词：

> 看我提供的完整动作，判断适合沉浸、动作小剧情还是观察互动。每条必须有真实起态、变化和结束，问题能由画面回答，不编人物心理或顾客成交。声音按实际条件选，没听净不称纯净环境声。用少量字幕完成整片、封面文案和检查，保留完整源区间与修订。

**验收与实际边界：** 三种不同叙事已有完整本机输出及画面/技术检查，环境声和音乐的完整听感仍待核。缺终态就换区间或补拍；原声不能公开就另做明确的音乐版；观察问题无答案就改问题，不靠首评编答案。

## 11｜产品知识与吃法

**输入：** 一个真实问题、对应产品资料及有效日期、标签/说明和实拍；若涉及处理，还需具体设备、初始状态及实际结果。

**步骤与工具：**

1. 选同口径比较、预算选择或真实处理展示。比较单位先统一；不能从价格和克重推导热量、营养或健康结论。
2. 做事实表：要说的内容、来源、日期、适用产品/条件、未知项。配料、过敏原、储存等只用对应资料，不把同类产品参数移植过来。
3. 将每句安排到对应证据画面：包装看身份，价签看价格，处理看条件，断面看结果。
4. 按[购物接单品](filming-remake.md)剪完整动作。等待可压缩，但不把视频秒数当加热时间；没有本款实测依据就不输出精确处理数字。
5. 检查合计、数量、单位及语义换行，完整听看后交事实表、视频、字幕、封面和文案。

可复制提示词：

> 回答【产品问题】，先核对应产品和当前公开资料。对比维度一致，预算含单价、单位与数量；吃法必须对应本款、设备和真实说明。缺温度或时间不猜，实际展示不冒充通用教程。让每句知识对应看得见的证据，完成完整作品和事实表，不新增营养、疗效或体验承诺。

**验收与实际边界：** 对比、预算与拆袋处理已有完整案例覆盖；精确复热处方没有跨产品验证。资料冲突先回来源核；单位不同就分列；数值跨行重排；画面是另一款就换源，不只改字幕。

## 14｜固定角色生活喜剧

**输入：** 一个生活小困扰、既有原创角色设定、具体动作与转折、可用声音及使用条件。不要把固定角色误解为每集只换一段文字。

**步骤与工具：**

1. 写“困扰→角色做什么→结果→一个可试的小办法”，同时写适用条件，不编专家背书或保证效果。
2. 给每场明确对象、动作和终态：东西装满、便签出现、做选择等。角色保持，动作与道具随新故事设计。
3. 用本机可用录音或合成音源先做一句，核文字与实际 WAV。可按最小语义单元分别合成，按真实长度拼接；没有字级边界就标语义段级，不能猜时码。
4. 用 HTML/Canvas/JavaScript 或等效动画工具把动作绑定实际时间。做小尺寸草稿，再看首尾、切点、乱序跳转和完整过程。
5. 配音、音乐、音效分轨，统一 PCM 后编码。音量测量只是技术依据，实际听感另审。
6. 导出完整视频和字幕，实际看人物、道具、动作与字；封面围绕冲突独立排版，再交标题、正文和工程。

可复制提示词：

> 用固定原创角色把【生活问题】演成一集小喜剧。写具体动作、结果和一个能试的办法，不做轮流放大的文字卡。先真实合成或录制一句，按实际声音建立时间，标明字幕精度，再完成动画、封面和文案。声音使用条件未核清就保留内部候选。实际没听过的部分写待审，失败留版本，不自动发布。

**验收与实际边界：** 本次已做38.8秒完整有声本机候选、动画工程、字幕、封面及技术/画面复核。所用 Windows 系统声音的公开分发条件没有核清，完整听感也待审，因此该成品没有作为公开可分发示例。本卡保留制作方法，不随附该声音。换成别的音源须重新核条件、实际合成和计时，不直接套旧时轴；不等于双人原生对白已验证。

**失败恢复：** 声音缺失先核本机接口，不静默转云服务；剧情改了同步修声音与时轴；动作错位修对应场景，别把整片加速；中断保留日志，只恢复受影响部分；同音机器稿回音频核听。

## 15｜代码动画与真实案例讲解

**输入：** 要解释的主题、受众、看完后的动作、可公开事实、已有作品或真实界面、已授权音频。

**两条路线：** 代码动画用对象移动讲清流程关系；案例讲解用真实作品和界面说明实际步骤。示意图可以解释概念，但不能冒充真实后台结果。

**步骤与工具：**

1. 用“问题→反复发生的困难→具体过程→真实成果→下一步”组织故事，每场一件事。先列允许说的事实，再写旁白。
2. 配音使用完整句子；复用缓存要核原语境和使用条件。实际声音决定时长，静态字数只作计划。
3. 每场写起止、口播、对象与动作/真实证据、字幕和来源。动画可用 HTML/GSAP、HyperFrames；案例可用 HTML 信息卡、真实截图与 FFmpeg。
4. 把输入、来源指纹、声音裁切、字幕时码、输出目录显式声明。预检只读，帮助或导入不能触发生成；输出到新版本。
5. 先看每场中点与切点、完整标题、边缘与界面可读性。动画的移动、归档和撤回应表达真实关系，不只是装饰。
6. 完整渲染，原声统一连续 PCM 后最后编码。检查全片、字幕、声音、首尾和封面，再交工程与打开即可看的页面。

可复制提示词：

> 把【主题】做成给【受众】看的完整讲解视频，目的是【下一步】。先判断代码动画还是实际案例更合适；用具体对象动作或真实界面说明过程，只说已核事实。声音优先用有权使用的录音，按实际时码安排场景。工具的预检不得自动生成或覆盖，完成后交视频、字幕、可编辑工程、来源和失败记录。案例页面不造数据，技术通过与完整听看分开。

**验收与实际边界：** 两条路线各有完整本机实例，实际验证的是五场横版结构；已有安全预检和来源/技术/视觉检查。没有证明任意场数、画幅、新配音服务或跨机器安装。缓存声音存在不等于在线服务当前可用，也不等于可公开再分发。公共仓库不附内部录音和系统字体。

**失败恢复：** 勾号或卡片压字就改布局，别删掉应展示的信息；断成单字就按语义换行；声音越界核真实时长；输出已存在另存；不能用空白帧凑缺素材，也不能忽略真实重叠警告来通过。
