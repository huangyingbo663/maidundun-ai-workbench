# 接手一项多人任务

先找到这次采用的任务卡、最近的交接和真实产物。若看见两个版本，查采纳记录或询问原写者，再决定从哪一版继续。遇到“继续”时，把已有文件与最近决定核对一遍。

1. **约定结果。** 用一句话写谁在什么条件下能用这份成果，再写一项可观察的通过标准。例如让第一次到场的人看卡片就能找对领取点。区分可在文件里验的文字和必须现场看的摆放。
2. **选择已有做法。** 找到上一回确实做成的例子，核对它需要的输入、工具、适用范围和样例输出。工具可用时先用小样读回结果。若没有可复用方法，把新试验和已验证步骤分别记录。
3. **认领文件。** 每项写明任务 ID、依赖、写者、产物路径和验收条件。把同一份产物交给一个写者，复核意见另存。交接负责人可以兼任小任务写者，涉及独立复核时，由另一位实际读产物的人留下记录。消息只发文件位置和发生的变化。
4. **遇到问题回到原件。** 上游未通过时，先处理上游。复核者打开当前文件，逐项核对标准，把问题位置、期望与实际结果退给写者。改动后的文件重新读回并绑定新版本。文件哈希可识别版本，业务判断来自读过内容的复核者。
5. **交给下一人。** 留下采用文件、复核证据、待办、下一位负责人、下一动作和停止条件。写明未知事项应向谁取得什么回执。换人前原写者停止编辑，新写者先读最新版本并确认认领。用户授权之外的外部操作留待有权限的人决定。

向用户交付时，给实际产物入口、已经逐项验过的范围和仍待确认的一件具体事。自己既写又看的结果可作为自检；独立验收须保留另一位复核者的真实记录。

在配套仓库中使用时，从[协作练习](../../docs/team-collaboration.md)选派工或接班入口。单独使用本 Skill 时，也可以在普通文本中维护上述字段。
