# 参考拆解 → 自有实拍拍摄卡

输出让操作者拿着就能拍的逐镜卡：每镜说明作用、画面、动作、声音计划、可引用事实和拍后检查。保留参考为什么吸引人的结构，再用用户自己的商品与动作实现；不承诺复刻流量，不把参考的素材或事实冒充用户的。

用户可以这样开始：

> 我想借鉴这条参考，拍【自己的产品】。我能提供【已核信息和场景】，请拆出值得保留的部分，给我可浏览、可打印的拍摄卡。缺什么真实动作就列成补拍清单。

## 先理解输入

- 参考可以是用户提供的本地视频、图文或逐镜描述。先用当前环境确实可用的能力读完整参考；无法访问媒体时，明确只基于已提供的部分，不编造镜头和声音。不要为生成拍摄卡自动购买服务或下载模型。
- 获取自己的产品名称、已核公开事实、可用场景、能拍的动作与已有素材。有现成资料就读取；只对会改变方案的关键缺口集中提问。
- 没有参考时，可按用户目标设计原创结构，并标明“原创方案”；不能称为已经拆解过某条参考。

## 拆到能拍，而不只列主题

将参考按完整镜头或叙事段记录：

| 观察 | 必须区分的内容 |
|---|---|
| 时段与作用 | 这一段用于吸引注意、展示细节、给证据、转折还是收尾 |
| 画面与动作 | 景别、机位、主体、完整动作及切换时机 |
| 信息 | 屏幕文字与实际口播分别记录，不能把字幕当听到的原声 |
| 声音 | 能实际听到的声音、未知部分、计划采用的自有声音分别写 |
| 适配选择 | 保留什么作用、换成哪个自有动作、为什么调整 |

先形成“参考作用 → 自有事实或动作 → 要补拍什么”的映射，再排逐镜计划。例如，参考的“打开包装揭示细节”可以变成自己的“切开产品展示切面”；没有真实产品或镜头支撑的效果，不用另一款商品冒充。

## 写卡片

每镜写清六件事：为什么拍、相机看哪里、手或主体怎么动、声音怎么处理、引用哪条已核事实、拍完检查什么。动作写成可以执行的一句话；开始和结束都留足画面，别只写“拍产品特写”。时长是剪辑计划，不能当已拍素材时长。

产品名称、数量、价格、规格等以本次输入为准；没有确认的信息不作为字幕或口播承诺。生成器只能检查字段和事实引用，AI仍须审阅动作、声音等自由文本中的事实。参考音乐、人物与原图的使用权另行处理，拍摄卡不代表再分发授权。

## 生成离线 HTML

仓库配有标准库示例：[使用说明与字段](../../examples/shot-cards/README.md)、[完整输入](../../examples/shot-cards/demo.json)。需要可打印文件时再读它们。只安装了本技能、没有随附示例目录时，先交付同字段的Markdown拍摄卡；要运行工具需取得同一项目的 `examples/shot-cards`，不要猜测本机私有路径或伪称已经运行。

在项目根目录运行：

```bash
python examples/shot-cards/generate.py --input examples/shot-cards/demo.json --output shot-cards-demo.html
```

实际使用先生成新的产品JSON，把 `--input` 换成它；输出采用新的相对文件名。Python 3.10或更新即可，不需要账号、第三方包或联网。工具默认保留旧输出；遇到同名错误就换版本名，不擅自删除旧文件。

## 交付前检查

1. 逐镜核对商品、动作、事实引用和顺序；让操作者能按卡执行，关键缺口单列。
2. 实际运行后打开HTML检查文字、卡片数量、总时长、窄屏和打印预览。命令成功不等于版式可读；没有打开就写“生成完成，视觉未检查”。
3. 交付输入JSON、HTML及需要补拍/核实的事项。说明是拍摄计划，不宣称成片、声音审核、平台发布或经营效果已完成。

此技能从逐句逐镜拆解、自有素材映射和拍后检查的方法中整理。公开示例仅含原创文字，无第三方原件、私有素材或账户依赖。
